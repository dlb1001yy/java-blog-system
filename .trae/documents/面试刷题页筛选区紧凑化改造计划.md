# 面试刷题页筛选区紧凑化改造计划

> 目标文件：`blog-app/subpkg-study/pages/interview/index.vue`
> 问题：「技术方向」多选 chips 全量换行铺开占 3~4 行，加上难度/刷题状态/搜索栏，筛选面板默认展开（`filterExpanded = ref(true)`）把题目列表挤出首屏，浏览不便。

## 一、现状分析（Phase 1 探索结论）

页面结构（单文件 919 行）：

```
interview-page (100vh)
└── scroll-view.container（整页滚动，触底分页）
    ├── filter-card（可折叠筛选面板，默认展开）
    │   ├── filter-header（筛选 + 计数角标 + 箭头）
    │   └── filter-body（v-show 展开）
    │       ├── filter-section 技术方向（多选，chip-row 全量换行 ← 问题根源）
    │       ├── filter-section 难度（单选 4 项）
    │       ├── filter-section 刷题状态（单选 3 项）
    │       └── filter-section 搜索栏
    └── list（题目卡片 / 骨架 / 空态 / 加载态）
```

关键现状：
- 技术方向来自 `api.getInterviewCategories()`，失败回退 6 项默认（`DEFAULT_CATEGORIES`），后端题库方向更多（十几个），chips wrap 后 3~4 行
- `.chip-row` 为 `flex-wrap: wrap`，无高度限制
- 面板已有折叠机制：`filterExpanded` + `v-show` + `.filter-arrow` 旋转，`activeFilterCount` 计数角标已存在——**默认收起只需改一行初始值**
- 项目内既有单行横向滚动模式：`components/CategoryChips.vue`（文章列表在用），但用户已选限高折叠方案
- 已确认的交互决策：技术方向采用**限高折叠**、面板**默认收起**

## 二、改造方案（frontend-skill 设计约束下的克制方案）

设计原则：不加新卡片、不加新颜色，沿用现有 chip 语言与 `$spacing`/`$radius` 令牌，动效复用页面既有的 0.2s ease 规范。只解决一个问题——把首屏还给题目列表。

### 修改点 1：技术方向 chips 限高折叠（核心）

**模板**（`filter-section` 技术方向块，约 L22-32）：

```html
<view class="filter-section">
  <text class="section-label">技术方向（多选）</text>
  <view class="chips-collapse">
    <view class="chip-row" :class="{ collapsed: !catsExpanded }">
      <!-- chips 循环不变 -->
    </view>
    <!-- 展开开关：仅当方向数量超出折叠阈值时渲染 -->
    <view v-if="categories.length > CAT_COLLAPSE_COUNT" class="collapse-toggle" @click="catsExpanded = !catsExpanded">
      <text>{{ catsExpanded ? '收起' : `展开 ${categories.length - CAT_COLLAPSE_COUNT} 个` }}</text>
      <view :class="['collapse-arrow', catsExpanded ? 'expanded' : '']">
        <Icon name="chevron-down" :size="14" />
      </view>
    </view>
  </view>
  <!-- 已选方向摘要：折叠时展示，避免选中项被藏起 -->
  <view v-if="!catsExpanded && selectedCategoryIds.length" class="selected-summary">
    已选 {{ selectedCategoryIds.length }} 个方向
  </view>
</view>
```

**脚本**（新增，放在 `filterExpanded` 附近）：

```js
// 技术方向折叠：折叠态以透明度渐隐模拟"2 行"高度（无需 JS 测量）
const CAT_COLLAPSE_COUNT = 8   // 约 2 行 chips 数量阈值
const catsExpanded = ref(false)
```

**样式**（新增于 `.chip-row` 附近）：

```scss
/* 折叠态：max-height 约 2 行 chips（行高 28px + gap 8px ≈ 64px），渐隐底缘提示可展开 */
.chip-row.collapsed {
  max-height: 64px;
  overflow: hidden;
  -webkit-mask-image: linear-gradient(to bottom, #000 70%, transparent 100%);
}

/* 展开开关：次级文字按钮，弱化于 chips */
.collapse-toggle {
  display: inline-flex;
  align-items: center;
  gap: 2px;
  margin-top: $spacing-xs;
  color: var(--app-primary, #059669);
  font-size: 12px;
}

.collapse-arrow {
  display: flex;
  transition: transform 0.3s ease;   /* 与 .filter-arrow 同规范 */
}

.collapse-arrow.expanded {
  transform: rotate(180deg);
}

/* 折叠时已选摘要：小字提示，防止选中项隐藏后不可见 */
.selected-summary {
  margin-top: $spacing-xs;
  font-size: 12px;
  color: var(--app-text-tertiary, #A8A29E);
}
```

> uni-app 多端说明：`-webkit-mask-image` 在 H5/小程序/App WebView 均可用；若某平台不支持则退化为纯截断（无渐隐），不影响功能。`max-height` 过渡因 chips 数量动态变化不保证平滑，采用直接切换（与 v-show 面板折叠行为一致，克制不做动画）。

### 修改点 2：筛选面板默认收起

```js
// 筛选面板展开态
const filterExpanded = ref(false)   // 原 true → false
```

现有 `activeFilterCount` 计数角标 + `.filter-arrow` 旋转已覆盖收起态的信息反馈，无其他改动。

### 修改点 3（顺带，2 行小改）：面板展开态的自折叠联动

技术方向折叠开关 `catsExpanded` 初始 `false`，与面板收起/展开互不干扰（面板用 v-show，内部状态保留），无需联动逻辑——**不做额外联动**，保持最简。

## 三、不做什么（明确边界）

- 不改后端接口、不改分页/筛选请求逻辑（`selectedCategoryIds`、`resetAndFetch` 等全部不动）
- 不引入 CategoryChips 组件复用（多选场景下选中项滚出可视区反而更糟，保持 wrap）
- 不加骨架屏/动效/新组件文件，全部改动收敛在本页面单文件内
- 难度、刷题状态、搜索栏布局不动（本身各占 1 行，不是问题源）
- 暗色模式：全部用既有 CSS 变量（`--app-primary`/`--app-text-tertiary`），自动适配

## 四、验证步骤

1. `npm run dev:h5`（或 HBuilderX 运行到浏览器）打开面试刷题页
2. 验证默认收起：进入页面首屏直接可见题目卡片，筛选头部仅一行 + 角标
3. 展开面板：技术方向默认显示约 2 行 + 渐隐底缘 + 「展开 N 个」按钮；已选方向时折叠态显示「已选 N 个方向」摘要
4. 点击展开/收起：chips 全量展示↔2 行限高，箭头旋转，已选项视觉状态保留
5. 功能回归：选方向/难度/状态/搜索后列表正确刷新；收藏、错题本、展开答案不受影响
6. 切换暗色模式：折叠渐隐、摘要文字、展开按钮颜色正常
7. App 端（如可用）：mask-image 渐隐是否生效不影响功能，截断即可
