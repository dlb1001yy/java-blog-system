# 统一文件上传链路接入三态存储策略（修复封面图不进 MinIO、桶不创建）

## 问题诊断（根因）

用户配置 `STORAGE_TYPE=minio` 后，观察到的两个现象均有明确根因：

| 现象 | 根因 |
|---|---|
| 后台启动后 MinIO 没有 `blog` 桶 | ① 桶为懒初始化（`ensureBucketExists` 仅在首次上传时触发），启动时不建桶；② 全项目实际**没有任何上传流量**走 `FileStorageService`，桶永远不会被创建 |
| 文章封面图没上传到 MinIO | 项目存在**两套并行上传体系**：封面图生成（`CoverImageGenerator`→`FileUtils.saveBytes`）、编辑器图片上传（`POST /admin/upload`→`AdminFileController`→`FileUtils.upload`）、导入首图转存（`MarkdownImportService`）三处全部硬编码写本地磁盘（`file.upload-path`），与 `storage.type` 完全无关。`FileStorageService`（local/minio/oss 三态）只有一个孤岛调用点 `StorageController`（`POST /v1/storage/upload`），前端从未调用 |

用户已确认：**docker compose 启动**（`.env` 生效，compose environment 段确认注入 `STORAGE_TYPE`/`MINIO_*`，无 IDE 读取 `.env` 问题）+ 选择**全面接入**方案。

## 改造方案

### 1. FileStorageService 接口新增 byte[] 入口

[FileStorageService.java](file:///d:/my-project/java-blog-system/blog-backend/src/main/java/com/dlbyy/blog/storage/FileStorageService.java) 新增：

```java
/**
 * 保存字节数组（封面图生成、外链图片转存等无 MultipartFile 场景）
 * @param data 文件内容
 * @param suffix 小写扩展名（如 "png"），不含点
 * @param contentType MIME 类型，可为 null（实现按 suffix 推断）
 * @param originalFilename 原始文件名，可为 null
 */
FileUploadResult saveBytes(byte[] data, String suffix, String contentType, String originalFilename);
```

三个实现同步实现（object key 生成复用各自 upload 的日期目录 + `时间戳_随机数.suffix` 规则）：

- **LocalFileStorageServiceImpl**：校验 data 非空 → 日期子目录 → `Files.write` → 返回 `urlPrefix + relativePath`（异常包装 BusinessException，与 upload 一致）
- **MinioStorageServiceImpl**：`ensureBucketExists()` → `putObject(PutObjectArgs... .stream(new ByteArrayInputStream(data), data.length, -1) .contentType(resolveContentType(suffix)))`；新增私有 `resolveContentType(suffix)`：jpg/jpeg→image/jpeg、png→image/png、gif→image/gif、webp→image/webp、md/markdown→text/markdown，其余 application/octet-stream（contentType 参数非空时优先）
- **AliyunOssStorageServiceImpl**：`ObjectMetadata meta = new ObjectMetadata(); meta.setContentLength(data.length); meta.setContentType(...)` → `ossClient.putObject(bucket, key, new ByteArrayInputStream(data), meta)`

### 2. FileUtils 改造：保留安全校验，落盘换策略

[FileUtils.java](file:///d:/my-project/java-blog-system/blog-backend/src/main/java/com/dlbyy/blog/utils/FileUtils.java)：
- 注入 `private final FileStorageService fileStorageService;`（加 `@RequiredArgsConstructor`，去掉 `uploadPath` 字段；`allowedTypes`/`maxSize` 两个 `@Value` 保留，用 `@RequiredArgsConstructor` + `@Value` 字段并存时改为构造器上 `@Value` 或保留字段注入——保持现状风格：字段 `@Value` + 手写构造器注入 fileStorageService，避免 Lombok 与 `@Value` 字段冲突）
- `upload(MultipartFile)`：保留全部校验与重编码逻辑，末段落盘改为：
  ```java
  FileUploadResult result = fileStorageService.saveBytes(data, suffix, file.getContentType(), originalFilename);
  return result.getUrl();
  ```
- 删除 `saveBytes()`、`ensureDestFile()` 方法（无引用后）；`file.upload-path` 配置保留（WebMvcConfig 静态映射仍在用）

### 6. 启动时预建 MinIO 桶（回应用户"启动后没建桶"）

- [MinioStorageServiceImpl.java](file:///d:/my-project/java-blog-system/blog-backend/src/main/java/com/dlbyy/blog/storage/impl/MinioStorageServiceImpl.java) 新增公有方法：
  ```java
  /** 启动时预建桶入口：失败仅告警不阻断应用启动（上传时仍会兜底重试） */
  public void ensureBucketReady() {
      try { ensureBucketExists(); }
      catch (Exception e) { log.warn("MinIO 启动预建桶失败（上传时将重试）: {}", e.getMessage()); }
  }
  ```
- [StorageAutoConfiguration.java](file:///d:/my-project/java-blog-system/blog-backend/src/main/java/com/dlbyy/blog/storage/StorageAutoConfiguration.java) 的 `minioFileStorageService` Bean 返回前调用 `service.ensureBucketReady()`（在 Bean 工厂方法内调用，MinIO 不可达时仅 warn，不影响启动）

## 假设与决策

1. **不做**：迁移存量本地文件到 MinIO、编辑器正文图片重写、StorageController 孤岛接口清理（保持不动，避免扩大范围）
2. local 模式新文件采用日期子目录（LocalFileStorageServiceImpl 既有行为），与旧平铺目录并存，静态映射均可服务
3. MinIO URL 为完整地址（`MINIO_URL_PREFIX=http://<ip>:9000/blog/`），桶匿名只读策略保证浏览器直接可访问；blog-app 的 `resolveFileUrl` 对完整 URL 原样透传，无需前端改动
4. `FileUploadResult` 字段不变（url/originalFilename/filename/size/storageType/path）
5. 沙箱限制 Maven 仓库写入，编译验证用 javac + 本地仓库 jar（同前次方案）；`mvn test` 由用户本机执行
