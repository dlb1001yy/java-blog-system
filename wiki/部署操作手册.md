## 1. 部署前准备

### 1.1 确认 Docker 已安装

```bash
docker --version
# 预期输出：Docker version 24.x.x 或更高

docker compose version
# 预期输出：Docker Compose version v2.x.x
```

### 1.2 确认代码已克隆

```bash
cd ~/java-blog-system
ls -la
```

预期看到以下关键文件：

```
docker-compose.yml
blog-backend/
blog-admin/
blog-frontend/
```

### 1.3 检查 Docker 相关文件

```bash
# 确认 Dockerfile 存在
ls blog-backend/Dockerfile blog-admin/Dockerfile blog-frontend/Dockerfile

# 确认 nginx 配置存在
ls blog-admin/nginx.conf blog-frontend/nginx.conf

# 确认 docker 配置存在
ls blog-backend/src/main/resources/application-docker.yaml

# 确认数据库初始化脚本存在
ls blog-backend/sql/01-create_sql.sql
```

### 1.4 查看服务器 IP

```bash
ip addr show | grep 'inet ' | grep -v '127.0.0.1'
# 记下虚拟机 IP，后续访问需要用到
```

## 2. Docker 镜像加速器配置

国内网络环境拉取 Docker Hub 镜像可能超时或被限流（429 Too Many Requests），**必须配置镜像加速器**。

### 2.1 查看当前配置

```bash
cat /etc/docker/daemon.json
```

### 2.2 配置镜像加速器

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://dockerpull.org",
    "https://docker.xuanyuan.me"
  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
EOF
```

### 2.3 重启 Docker 生效

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 2.4 验证镜像加速

```bash
docker info | grep -A 5 "Registry Mirrors"
```

### 2.5 （推荐）配置阿里云专属加速器

公共镜像加速器可能被限流，阿里云提供免费的个人专属加速器，稳定性最好：

1. 访问 https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors
2. 使用阿里云账号登录
3. 页面会显示你的专属加速器地址，格式类似：`https://xxxxxx.mirror.aliyuncs.com`
4. 替换 daemon.json：

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://xxxxxx.mirror.aliyuncs.com",
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

> 将 `xxxxxx` 替换为你的阿里云加速器 ID。

## 3. 基础镜像预拉取

在执行 `docker compose up` 之前，建议先单独拉取所有基础镜像。这样可以避免构建时因镜像拉取超时而失败，也便于排查网络问题。

### 3.1 需要拉取的镜像列表

按服务依赖顺序排列：

| 序号 | 镜像名称 | 用途 | 大小参考 | 拉取命令 |
|------|----------|------|----------|----------|
| 1 | `mysql:8.0` | 数据库 | ~600MB | `docker pull mysql:8.0` |
| 2 | `redis:7-alpine` | 缓存 | ~40MB | `docker pull redis:7-alpine` |
| 3 | `eclipse-temurin:17-jdk-jammy` | 后端构建阶段 | ~350MB | `docker pull eclipse-temurin:17-jdk-jammy` |
| 4 | `eclipse-temurin:17-jre-jammy` | 后端运行阶段 | ~250MB | `docker pull eclipse-temurin:17-jre-jammy` |
| 5 | `node:18-alpine` | 前端构建阶段 | ~150MB | `docker pull node:18-alpine` |
| 6 | `nginx:1.25-alpine` | 前端运行阶段 | ~50MB | `nginx:1.25-alpine` |

> **说明**：`eclipse-temurin:17-jdk-jammy` 与 `eclipse-temurin:17-jre-jammy` 共享 Ubuntu jammy 基础层，拉取第一个后第二个会快很多。

### 3.2 逐个拉取镜像

```bash
# 1. 拉取 MySQL（最先需要）
docker pull mysql:8.0

# 2. 拉取 Redis
docker pull redis:7-alpine

# 3. 拉取后端构建镜像（JDK，较大）
docker pull eclipse-temurin:17-jdk-jammy

# 4. 拉取后端运行镜像（JRE，与 JDK 共享层，很快）
docker pull eclipse-temurin:17-jre-jammy

# 5. 拉取前端构建镜像
docker pull node:18-alpine

# 6. 拉取前端运行镜像
docker pull nginx:1.25-alpine
```

### 3.3 验证镜像已拉取

```bash
docker images | grep -E 'mysql|redis|eclipse-temurin|node|nginx'
```

预期输出包含以上 6 个镜像。

### 3.4 如果拉取超时或 429

```bash
# 查看拉取错误信息
docker pull mysql:8.0 2>&1 | tail -5

# 解决方案：
# 1. 确认镜像加速器已配置（见第 2 节）
# 2. 使用阿里云专属加速器（见第 2.5 节）
# 3. 重试拉取
docker pull mysql:8.0
```

## 4. 一键启动全部服务

### 4.1 执行启动命令

```bash
cd ~/java-blog-system
docker compose up -d --build
```

- `-d`：后台运行
- `--build`：构建镜像（首次必须加）

### 4.2 启动顺序说明

Docker Compose 按依赖顺序启动服务：

```
MySQL（启动 + 健康检查通过）
    ↓
Redis（启动 + 健康检查通过）
    ↓
blog-backend（Maven 编译 → JAR 打包 → 启动 → 健康检查通过）
    ↓
blog-admin（npm 编译 → nginx 启动）
blog-frontend（npm 编译 → nginx 启动）
```

### 4.3 启动进度查看

```bash
# 查看全部服务实时日志
docker compose logs -f

# 单独查看后端构建与启动日志（最耗时的部分）
docker compose logs -f blog-backend

# 当后端日志出现以下字样时，说明后端已启动成功：
# "Started JavaBlogApplication in x.xxx seconds"
```

### 4.4 首次构建耗时参考

| 阶段 | 预计耗时 | 说明 |
|------|----------|------|
| MySQL + Redis 启动 | 30-60s | 基础服务就绪 |
| 后端 Maven 依赖下载 | 3-10min | 首次需下载所有依赖（走阿里云 Maven 镜像） |
| 后端编译打包 | 1-2min | Maven 编译 + JAR 打包 |
| 后端启动 | 30-60s | Spring Boot 启动 |
| 管理后台 npm install + build | 2-5min | 首次需下载 npm 依赖 |
| 前台门户 npm install + build | 2-5min | 首次需下载 npm 依赖 |
| **总计** | **8-20min** | 取决于网络与服务器性能 |

> 后续重新构建会利用 Docker 缓存层，耗时大幅减少。

## 5. 逐服务状态检查

### 5.1 查看全部服务状态

```bash
docker compose ps
```

预期输出（全部为 `running` 或 `healthy`）：

```
NAME              IMAGE                              STATUS                    PORTS
blog-admin        blog-admin                         Up X minutes              0.0.0.0:8081->80/tcp
blog-frontend     blog-frontend                      Up X minutes              0.0.0.0:8082->80/tcp
blog-backend      blog-backend                       Up X minutes (healthy)    0.0.0.0:8080->8080/tcp
blog-mysql        mysql:8.0                          Up X minutes (healthy)    0.0.0.0:3306->3306/tcp
blog-redis        redis:7-alpine                     Up X minutes (healthy)    0.0.0.0:6379->6379/tcp
```

### 5.2 健康检查说明

| 服务 | 健康检查方式 | start_period |
|------|-------------|--------------|
| MySQL | `mysqladmin ping` | 30s |
| Redis | `redis-cli ping` | 10s |
| blog-backend | `curl http://localhost:8080/api/portal/stats` | 60s |

> `blog-backend` 的健康检查 `start_period` 为 60 秒，在此期间即使检查失败也不会标记为 unhealthy。

### 5.3 查看各服务日志

```bash
# 查看后端日志（排查启动失败）
docker compose logs -f blog-backend

# 查看 MySQL 日志
docker compose logs -f mysql

# 查看 Redis 日志
docker compose logs -f redis

# 查看管理后台日志
docker compose logs -f blog-admin

# 查看前台门户日志
docker compose logs -f blog-frontend
```

### 5.4 检查容器资源占用

```bash
docker stats --no-stream
```

## 6. 访问测试

将下文中的 `<服务器IP>` 替换为实际 IP（本机部署使用 `localhost`，使用 `ip addr` 查看）。

### 6.1 测试后端 API

```bash
# 测试后端是否正常响应
curl http://localhost:8080/api/portal/stats

# 预期返回 JSON 数据，包含 articleCount、viewCount、categoryCount 等字段
```

### 6.2 测试接口文档

浏览器访问：

```
http://<服务器IP>:8080/api/doc.html
```

预期显示 Knife4j 接口文档页面。

### 6.3 测试前台门户

浏览器访问：

```
http://<服务器IP>:8082/blog/
```

> **注意**：路径必须包含 `/blog/` 子路径，访问根路径会自动重定向。

预期显示博客前台首页，能看到文章列表、统计数据等。

### 6.4 测试管理后台

浏览器访问：

```
http://<服务器IP>:8081/admin/
```

> **注意**：路径必须包含 `/admin/`（含尾部斜杠）。

预期显示管理后台登录页面。使用默认账号登录：

| 用户名 | 密码 |
|--------|------|
| admin | admin123 |

登录后预期看到 Dashboard 仪表盘页面。

### 6.5 测试上传功能

在管理后台编辑文章时上传图片，确认图片可正常上传并显示：

```bash
# 检查上传目录是否有文件
docker exec blog-backend ls -la /app/uploads/

# 检查上传文件可访问
curl -I http://localhost:8080/api/uploads/
```

### 6.6 访问地址汇总

| 服务 | 地址 | 说明 |
|------|------|------|
| 前台门户 | http://\<服务器IP\>:8082/blog/ | 博客前台（路径含 /blog/） |
| 管理后台 | http://\<服务器IP\>:8081/admin/ | 管理后台（路径含 /admin/） |
| 后端 API | http://\<服务器IP\>:8080/api | 后端接口 |
| 接口文档 | http://\<服务器IP\>:8080/api/doc.html | Knife4j 文档 |

如配置了外部 Nginx（80 端口）统一入口，也可通过以下地址访问：

| 服务 | 地址 |
|------|------|
| 前台门户 | http://\<服务器IP\>/blog/ |
| 管理后台 | http://\<服务器IP\>/admin/ |

## 7. 常见部署问题排查

### 7.1 镜像拉取 429 Too Many Requests

**现象**：

```
failed to resolve source metadata for docker.io/library/xxx: unexpected status from GET request: 429 Too Many Requests
```

**原因**：公共镜像加速器被限流。

**解决**：

```bash
# 1. 配置阿里云专属加速器（见第 2.5 节）
# 2. 重启 Docker
sudo systemctl restart docker
# 3. 重试拉取
docker pull <镜像名>
```

### 7.2 后端构建 apt-get 超时

**现象**：`docker compose up --build` 卡在 `RUN apt-get update` 超过 5 分钟。

**原因**：容器内 `apt-get` 从 `archive.ubuntu.com` 下载缓慢。

**解决**：当前 Dockerfile 已移除 `apt-get`，使用 Docker `ADD` 指令直接下载 Maven。如仍遇到此问题，确认使用的是最新 Dockerfile：

```bash
# 检查 Dockerfile 是否包含 ADD 指令（而非 apt-get）
grep "ADD" blog-backend/Dockerfile
```

### 7.3 Maven 下载慢 / 构建卡住

**现象**：后端构建卡在 `mvn dependency:go-offline` 或 `mvn package` 超过 10 分钟。

**原因**：Maven 从中央仓库下载依赖缓慢。

**解决**：当前 Dockerfile 已配置阿里云 Maven 镜像。确认配置存在：

```bash
grep "aliyun" blog-backend/Dockerfile
# 预期看到阿里云 Maven 镜像 URL
```

如仍慢，可手动在宿主机预编译 JAR 后修改 Dockerfile 直接复制：

```bash
# 在宿主机（需有 JDK + Maven）
cd blog-backend
mvn clean package -DskipTests
# 然后修改 Dockerfile 跳过编译阶段，直接 COPY target/*.jar
```

### 7.4 端口冲突

**现象**：容器启动报错 `bind: address already in use`。

**解决**：

```bash
# 查看占用端口的进程
sudo lsof -i :8080
sudo lsof -i :8081
sudo lsof -i :8082

# 停止占用进程
sudo kill -9 <PID>

# 或修改 docker-compose.yml 中的端口映射
# 例如将 "8080:8080" 改为 "9090:8080"
```

### 7.5 数据库连接失败

**现象**：后端日志报错 `Communications link failure` 或 `Access denied for user 'root'`。

**解决**：

```bash
# 1. 确认 MySQL 容器已健康启动
docker compose ps mysql
# 状态应为 healthy

# 2. 检查后端配置中的数据库连接信息
cat blog-backend/src/main/resources/application-docker.yaml | grep -A 5 datasource
# host 应为 mysql，password 应为 123456

# 3. 手动测试数据库连接
docker exec blog-mysql mysql -uroot -p123456 -e "SHOW DATABASES;"
# 应看到 dlbyy_zp_blog 数据库

# 4. 如数据库未初始化，手动执行 SQL
docker exec -i blog-mysql mysql -uroot -p123456 dlbyy_zp_blog < blog-backend/sql/01-create_sql.sql
```

### 7.6 前端页面空白 / 404

**现象**：访问管理后台或前台门户显示空白页或 404。

**解决**：

```bash
# 1. 确认后端健康检查通过（前端依赖后端）
docker compose ps blog-backend
# 状态应为 healthy

# 2. 管理后台必须访问 /admin/ 路径（含尾部斜杠）
# 正确：http://<IP>:8081/admin/
# 错误：http://<IP>:8081/

# 3. 前台门户必须访问 /blog/ 路径（含子路径）
# 正确：http://<IP>:8082/blog/
# 错误：http://<IP>:8082/

# 4. 检查 nginx 配置
docker exec blog-admin cat /etc/nginx/conf.d/default.conf
docker exec blog-frontend cat /etc/nginx/conf.d/default.conf

# 5. 检查前端构建产物是否存在
# 管理后台产物在 html/admin/ 子目录
docker exec blog-admin ls /usr/share/nginx/html/admin/
# 前台门户产物在 html/blog/ 子目录
docker exec blog-frontend ls /usr/share/nginx/html/blog/
```

### 7.7 后端健康检查不通过

**现象**：`docker compose ps` 显示 blog-backend 状态为 `unhealthy`。

**解决**：

```bash
# 查看后端日志
docker compose logs --tail 50 blog-backend

# 常见原因：
# - 数据库未就绪：等待 MySQL healthy 后重启后端
docker compose restart blog-backend

# - 应用启动报错：查看日志中的异常堆栈
# - 健康检查接口无响应：手动测试
docker exec blog-backend curl http://localhost:8080/api/portal/stats
```

### 7.8 npm install 慢

**现象**：前端构建卡在 `npm install` 超过 10 分钟。

**解决**：当前 Dockerfile 已配置 npmmirror 镜像源。如仍慢：

```bash
# 确认 Dockerfile 中有 --registry 参数
grep "registry" blog-admin/Dockerfile blog-frontend/Dockerfile
# 预期看到 https://registry.npmmirror.com
```

## 8. 停止与重新部署

### 8.1 停止全部服务

```bash
cd ~/java-blog-system
docker compose down
```

> 此命令仅停止并删除容器，**不删除数据卷**，数据保留。

### 8.2 停止并清除数据（⚠️ 慎用）

```bash
# 停止并删除容器 + 数据卷（清空所有数据）
docker compose down -v
```

### 8.3 清理构建缓存

```bash
# 清理 Docker 构建缓存（解决构建异常）
docker builder prune -f

# 清理无用的镜像和容器
docker system prune -f
```

### 8.4 更新代码后重新部署

```bash
cd ~/java-blog-system

# 1. 拉取最新代码
git pull origin main

# 2. 重新构建并启动（仅重建有变更的服务）
docker compose up -d --build

# 3. 查看启动状态
docker compose ps
```

### 8.5 仅重建单个服务

```bash
# 仅重建后端
docker compose up -d --build blog-backend

# 仅重建管理后台
docker compose up -d --build blog-admin

# 仅重建前台门户
docker compose up -d --build blog-frontend
```

### 8.6 查看数据卷

```bash
# 列出数据卷
docker volume ls | grep blog

# 查看数据卷详情
docker volume inspect blog_mysql_data
docker volume inspect blog_redis_data
docker volume inspect blog_uploads_data
```

### 8.7 进入容器排查

```bash
# 进入后端容器
docker exec -it blog-backend bash

# 进入 MySQL
docker exec -it blog-mysql mysql -uroot -p123456

# 进入 Redis
docker exec -it blog-redis redis-cli -a 123456

# 进入管理后台 nginx
docker exec -it blog-admin sh

# 进入前台门户 nginx
docker exec -it blog-frontend sh
```
