## 用户需求
为 java-blog-system 实现完整的安全认证增强方案，覆盖密码安全、令牌刷新、登录限流三大模块。

## 产品概述
在现有 Spring Boot + Spring Security + JWT 认证体系之上，补全密码加密与强度校验、双令牌刷新（access 15min / refresh 7d，refresh 存 HTTP-only Cookie）、基于 IP 与用户名的多层登录限流与账户锁定能力，并支持令牌黑名单主动吊销。同步改造 admin 前端实现令牌过期自动静默刷新。

## 核心功能
- 密码加密存储：注册/初始化/改密时使用 BCrypt（强度 12 轮）对密码哈希，数据库不再存明文；新增密码强度校验（至少 8 位，含大小写字母、数字、特殊字符）。
- 双令牌刷新：颁发 15 分钟访问令牌与 7 天刷新令牌；刷新令牌通过 HTTP-only + Secure + SameSite Cookie 下发，前端无法用 JS 读取；访问令牌过期后前端自动用刷新令牌静默换取新访问令牌，无需重新登录；登出与主动吊销时双令牌均加入黑名单/失效。
- 登录限流保护：单 IP 每分钟最多 5 次登录尝试；同一用户名连续失败 5 次锁定账户 15 分钟；记录失败次数与最后失败时间；超限返回明确错误提示；达到锁定阈值触发告警通知；限流参数通过配置文件动态调整。


## 技术栈
- 后端：Spring Boot 3 + Spring Security 6 + jjwt（HS512）+ MyBatis-Plus + Redis（限流/黑名单/失败计数）+ MySQL
- 前端：Vue3 + Pinia + Axios（blog-admin）
- 复用现有：`BCryptPasswordEncoder`、`JwtUtils`、`RateLimitAspect`+`rate_limit.lua`、`CustomUserDetailsService`、`SecurityConfig`

## 实现方案
### 总体策略
围绕“加密-颁发-防护”三道防线增强现有认证链路，尽量复用已有组件，新增独立服务/配置类并通过配置化注入参数，避免改动无关逻辑。

### 关键技术决策
1. **BCrypt 强度 12 轮**：在 `SecurityConfig` 中显式 `new BCryptPasswordEncoder(12)`；新建 `PasswordStrengthValidator` 工具类做正则强度校验，注册/改密接口统一调用。
2. **Refresh Token 存 HTTP-only Cookie**（最优）：
   - 登录成功时后端通过 `HttpServletResponse.addCookie` 下发 refresh token，属性 `HttpOnly=true; Secure=true; SameSite=None; Path=/api/auth; Max-Age=604800`。
   - `/auth/refresh` 从 Cookie 读取，不再依赖前端传参；前端 `localStorage` 仅保留 access token。
   - 刷新令牌签发时写入 Redis（`refresh:{jti}` 或 `{username}` 集合），登出/锁定/改密时统一吊销；黑名单复用现有 `jwt:blacklist:` 机制覆盖 access 与 refresh 两类 token。
3. **登录限流配置化 + 用户名锁定**（最优）：
   - 新增 `SecurityProperties`（@ConfigurationProperties(prefix="security.login")）承载 ipLimit/count/window、userFailThreshold、lockMinutes、alertEnabled 等参数。
   - 新增 `LoginAttemptService`：IP 维度复用现有 Redis+Lua 滑动窗口（参数从配置读取）；用户名维度用 Redis 记录连续失败次数与锁定到期时间（Key：`login_fail:{username}`、`lock:{username}`）。
   - 登录失败时累加计数，达阈值写入锁定 Key 并返回明确提示；登录成功后清除计数。`RateLimit` 注解的默认 count 改为从配置读取（保留兼容）。
   - 达到锁定上限时调用告警钩子（默认日志 warn + 预留 `AlertNotifier` 接口便于接入邮件/Webhook）。

### 性能与可靠性
- 失败计数与锁定完全基于 Redis，避免高频写库；使用 `EXPIRE` 自动清理冷数据。
- 限流 Lua 脚本原子执行，无 N+1；Cookie/Redis 操作均在登录关键路径，开销可忽略。
- `SameSite=None` 需配合 `Secure`，本地 HTTP 下由配置开关控制（dev 环境关闭 Secure 便于联调）。

## 实现要点（防回归）
- 不改动 `JwtUtils` 黑名单核心逻辑，仅调整 `ACCESS_TOKEN_EXPIRATION` 为 15min 并扩展 refresh 吊销 API。
- 前端 `request.js` 响应拦截器新增 401 时调用 `user.refreshToken()` 用同一 refresh 请求二次重试，避免登录页闪烁；并发刷新用 Promise 去重。
- 保留 `/auth/**` permitAll，刷新与登出接口仍需匿名可访问。
- 密码强度校验在注册（`UserController`/管理端）、改密接口统一接入，错误返回 400 明确信息。

## 架构设计
```mermaid
flowchart TD
    A[前端登录] --> B[AuthController.login]
    B --> C[LoginAttemptService.IP限流]
    B --> D[Spring Security 认证]
    D --> E[CustomUserDetailsService 校验锁定/状态]
    D --> F[密码 BCrypt 校验]
    B --> G[颁发 access+refresh Cookie]
    H[access 过期] --> I[前端 request 拦截器 401]
    I --> J[/auth/refresh 读 Cookie]
    J --> K[校验 refresh 黑名单/锁定]
    K --> G
    L[登录失败] --> M[LoginAttemptService 记失败+锁定]
    M --> N[超限告警 AlertNotifier]
```

## 关键代码结构（摘要）
- `SecurityProperties`：字段 `ipLimitCount=5, ipWindowSeconds=60, userFailThreshold=5, lockMinutes=15, alertEnabled=true, bcryptStrength=12, cookieSecure=true`。
- `LoginAttemptService`：方法 `boolean tryAcquireIp(String ip)`、`void onLoginFailure(String username)`、`boolean isLocked(String username)`、`void onLoginSuccess(String username)`、`void alertLock(String username)`。
- `PasswordStrengthValidator`：`boolean isValid(String pwd)` / 明确错误信息枚举。


## Agent Extensions
### SubAgent
- **code-explorer**
  - Purpose: 在实现前深度扫描注册/改密/管理员初始化等所有写入密码的代码路径，确保 BCrypt 加密与强度校验无遗漏接入点
  - Expected outcome: 输出所有涉及密码写入/变更的 Controller/Service 文件清单与行号，供实现阶段精确修改
